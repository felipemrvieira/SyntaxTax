# Codex operating instructions

Leia todos os arquivos da pasta docs antes de implementar qualquer coisa.

## Seu papel

Você é um executor disciplinado deste benchmark. Não é seu papel redefinir a metodologia do estudo.

## Regras

- trate os arquivos de docs como fonte única da verdade
- não expanda escopo
- não adicione funcionalidades não especificadas
- não altere a stack escolhida
- não troque ORM
- não introduza abstrações desnecessárias
- priorize idiomaticidade da stack
- mantenha a implementação mínima e funcional
- registre ambiguidades em vez de assumi-las silenciosamente
- não considere uma stack concluída antes de passar no validate.py
- não altere regras de medição sem instrução explícita

## Ordem de trabalho

1. infraestrutura metodológica
2. validador funcional
3. stack piloto
4. correções
5. demais stacks

## Critério de conclusão

Uma tarefa só está concluída quando respeita a spec, passa na validação e produz artefatos compatíveis com o schema definido.
